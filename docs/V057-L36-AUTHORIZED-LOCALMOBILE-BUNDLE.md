# v0.57 L36-Authorized LocalMobile Release Bundle

## Goal

v0.57 closes the Android release-binding gap.

A LocalMobile bundle is no longer considered a production-capable source merely
because it contains a mobile package, tokenizer, prompt contract and bootstrap
state. The production loader now requires the bundle to be cryptographically
bound to the exact checkpoint named by a COMPLETE L36 promotion ceremony.

This wave still does not claim real-device completion. It establishes the
authority chain and reproducible Android release workflow.

## Production bundle schema

`NOLANE-V057-AUTHORIZED-LOCALMOBILE-BUNDLE-V1`

Production authority:

`L36_COMPLETE_PROMOTION_CEREMONY`

The manifest binds:

- exact source checkpoint SHA-256;
- native mobile package manifest SHA-256;
- tokenizer.json SHA-256;
- tokenizer_config.json SHA-256;
- frozen prompt-contract file SHA-256;
- bootstrap-state file SHA-256;
- promotion ceremony semantic SHA-256;
- promotion authorization SHA-256;
- promotion ceremony file SHA-256.

The native package manifest must name the same source checkpoint.

## Strict loader

`LocalMobileProductRuntime::load()` is the production path.

It rejects:

- source/court bundles without L36 release authority;
- malformed digests;
- asset hash drift;
- mobile package checkpoint drift;
- missing or non-COMPLETE promotion ceremony;
- ceremony checkpoint mismatch;
- ceremony authorization mismatch;
- ceremony digest mismatch.

`load_for_court()` is intentionally separate and accepts only the explicit
`SYNTHETIC_COURT_ONLY_NO_RELEASE_AUTHORITY` marker used by the deterministic
source fixture. The Android Tauri shell never calls this court-only entrypoint.

## Staging-time authority verification

`scripts/stage_mobile_release_assets.py` is the canonical production staging
surface.

Before any resource is copied, it:

1. verifies the L36 ceremony with `require_complete=True`;
2. extracts the exact authorized checkpoint SHA-256;
3. fully verifies the native mobile package against that checkpoint;
4. verifies tokenizer assets;
5. verifies the frozen product prompt contract against those tokenizer bytes;
6. verifies the bootstrap persistent state against the same checkpoint and
   latent dimension;
7. only then writes the production LocalMobile manifest.

The staging operation never creates promotion authority. It only projects
already-existing COMPLETE L36 evidence into Android release resources.

## Bootstrap state

A fresh Android installation needs a valid state before the first user turn.

`scripts/build_mobile_release_bootstrap.py` reads the exact promoted
factorized checkpoint, verifies its SHA-256, obtains the checkpoint latent
dimension and writes a neutral zero-vector persistent latent.

This matches the desktop product behavior for a fresh identity/checkpoint:
persistent neural latent starts at zero until real interaction/adaptation
changes it.

The bootstrap identity is a sentinel only. LocalMobile replaces it with a
fresh device-local identity on first launch.

## Prompt contract

`scripts/freeze_mobile_release_prompt.py` loads only the supplied local
tokenizer assets and freezes the exact product chat-template contract used by
native Rust prompt rendering.

No network model object is required at Android runtime.

## Android release workflow

`.github/workflows/product-android-release.yml` accepts:

- promoted factorized checkpoint URL + exact SHA-256;
- COMPLETE L36 ceremony URL;
- tokenizer archive URL + exact SHA-256.

It then:

1. verifies HTTPS and downloaded hashes;
2. exports the native mobile package from the exact promoted checkpoint;
3. freezes the local tokenizer prompt contract;
4. creates the neutral checkpoint-bound bootstrap;
5. stages the L36-authorized LocalMobile bundle;
6. runs the strict Rust authority smoke;
7. builds the aarch64 Android APK;
8. publishes the APK together with LocalMobile manifest and ceremony evidence.

## CI authority court

Normal CI must not depend on real private promotion evidence.

The deterministic source fixture remains marked
`SYNTHETIC_COURT_ONLY_NO_RELEASE_AUTHORITY` and must fail the strict loader.

A separate test-only script constructs a syntactically valid COMPLETE ceremony
for the deterministic checkpoint. CI passes that ceremony through the same
production staging script and then proves that the strict loader accepts the
resulting staged bundle.

This proves the mechanics only. The synthetic ceremony is generated by a
test-only script and is not evidence that a real candidate passed L36.

## Explicit non-claims

v0.57 does not prove:

- that a real L36-authorized Android release has been run;
- clean install on an emulator or physical device;
- full mobile LivingEngine transition/rest/initiative/learning parity;
- latency, RAM, thermal or battery fitness.

Those remain mandatory gates before Android LocalMobile is called
production-complete.
